## 1. What we built and why

Milestone 2 measured implied volatility (IV) per company and session. Milestone 3 asks the study's four event
questions and tests them, after checking that the tests have the right size on this very data.

1. **`event_window_obs`** (committed, 89,389 rows): rel_day −60 … +10 around day 0 for each of the 1,259 events with
   no exclusion. Per session: observed, in the clean baseline and if not why not, ln IV, the abnormal log IV
   (mean-adjusted committed, VIX-adjusted local), the front-expiry IV in the window, σ_d and E.
2. **`event_measures`** (committed, 1,353 rows, 1:1 with `events`): eligibility per measure with its first failing
   reason, the baseline counts and means, β per company, the scale s_i, the tested quantities RUNUP, CRUSH, PERSIST_1,
   _5, _10 and ΔSIGMA_D (VIX-adjusted, local), their mean-adjusted twins and the standardised values SA_i (local),
   and the IV columns of `event_iv`.
3. **The statistics layer** (`src/earnings_vol/stats/`): two-way cluster-robust t, the Rademacher enumeration,
   BMP, KP and KPP, Patell, sign and rank tests, Holm and BH, all on hand-worked oracles.
4. **Gate G1** (`stats/g1.py`): 2,000 seeded null replications per design on the real event structure, every input
   re-estimated by the package's own code, a design calibrated on the real baselines, 18 stress designs and a power
   curve. H1–H3 are simulated on a cm30 series; H4 on a σ_d series of its own with its own calibration (added after
   the review, §9 F5), adjusted, as production adjusts ΔSIGMA_D, with the cm30 series' β on the same ln VIX path
   (second round, D5). Robustness rates within one point of the 6.30% bar are re-measured on 10,000 replications
   (second round, D3). **It ran before any H1–H4 result was computed** (`stats/run.py --g1` must exist before the
   results run).
5. **`results`** (committed, 786 rows): H1–H4, their robustness rows and mean-adjusted twins, H2's season-cut
   counterfactual, exploratory rows, the mean abnormal paths with two-way bands, G1's sizes (with the three
   re-measured rates) and both calibrations. A reference-distribution invariant runs on every write and read.
   Robustness rows that G1 finds mis-sized keep their estimate and lose their p-value (§9 F6, second round D3).
6. **Contract 0.4.0** and the app: `tests.json`, `event_paths.json`, `terrain.json`, `heatmap.json`; a Results page,
   animated crush paths, a heatmap, and the 3D terrain drawing real data (still lazy-loaded). Every page that shows a
   result says the timing labels are provisional.
7. **The notebook** `notebooks/03_event_study.ipynb`, generated by `tools/build_notebooks.py`.

## 2. Why this design

| Choice | Alternatives | Why | Cost |
|---|---|---|---|
| One window matrix (N events × 71 sessions) through **pure numpy functions** (`panel/abnormal.py`), used by the production run **and** by G1 | Separate code for the simulation | G1 must size the code that makes the reported rows (ADR 0005 §5) | The production run reads its matrices back from `event_window_obs` |
| ALIV **from the levels**, the span-change walk for the weights | Sum span changes for the value too | The level formula is the definition; the walk gives the variance weights. `test_ramp_identity.py` proves them equal to 1e-12 on the ADR's six cases | Two code paths that must agree (they are tested to) |
| β pools the clean one-session baseline changes of **every** event of a company whose baseline passes the 20/15 minimum, each date once | Daily events only; every non-excluded event (the first build, §9 F2) | ADR 0004 §1: an event below the minimum "gets no baseline"; dedupe because two baselines can share a date. β uses no session of any event window, but it does use the baselines of *later* events, which ADR 0004 §2 allows ("a description of the past, not a forecast") | Coarse-era Fri→Mon changes of passing coarse baselines enter β |
| VIX-adjusted per-row values **local**, β renamed `beta_vix_cboe` | Commit them under the owner's decision | The owner's decision of 2026-10-29 (ADR 0001 §7) allows committing Cboe-derived values the apps and docs need; no view needs the per-event market-adjusted values, so they stay local by preference. Aggregates are committed | `data/derived/` cannot reproduce the market-adjusted tests without FRED `VIXCLS` |
| The `results` invariant **in the registry** (`Table.invariant`, run by `store.validate`) | A check in the stats run only | "On every write": a regression row of milestone 4 is checked by the same writer | Core imports scipy |
| G1 **before** results, enforced by the run order | One run that does both | A failed gate moves a hypothesis out of the family before its p-value exists | Two commands |
| Calibrated noise has a **common share** κ | Stale quotes only (the ADR's lag-1 design) | The real cross-company lag-1 correlation is **negative** (−0.063), which stale quotes cannot produce; a common transient noise can (κ ρ₁) | One more parameter; the moment check reproduces this moment (z −0.2, §6.1) |
| AR of levels corrected for **quote noise and short windows** | The plain pooled estimate (0.736) | Noise inflates the lag-0 sum; Kendall's bias is −(1+3φ)/L at L ≈ 30. Corrected: 0.985 | The AR moment is **not** reproduced: panels simulated at the calibrated φ read 0.9985 ± 0.0040 (z −3.3), and a round trip at φ = 0.90 reads 0.96. The design is *less* mean-reverting than the data, so stricter for the ramps (§6.1, §9 F5) |
| H4 simulated on **its own σ_d series**, calibrated on the σ_d baselines and ΔSIGMA_D | H4 on the cm30 series (the first build) | ΔSIGMA_D is a change of ln σ_d, whose noise (ρ₁ −0.33), same-date correlation and day-0 ratio differ from cm30's | A second calibration and series per replication (§9 F5) |
| The DGP's scale **sig0 calibrated** (exp of the mean ln s_i over the change-variance factor) | The prototype's fixed 0.03 | Parameters in log points (company effect, drift, a power shift) must sit on the real scale; σ_d's sig0 is 0.049, cm30's 0.034 | The power curves in log points moved (§6.1); it also lowered H4's robustness rates by 0.6–1.3 points without moving the primaries (§9, second round D3) |
| H4's σ_d series adjusted with **the cm30 series' β, on the same ln VIX path** (`g1.second_series`) | β re-estimated on the simulated σ_d series, with its own VIX path (the first fix round) | Production computes ΔSIGMA_D = Δln σ_d − β Δln VIX with the cm30 β (`window.py:221`); G1 must size that statistic (ADR 0005 §5) | The second series depends on the first's β estimate; σ_d's own loading on VIX is assumed equal to cm30's (§9, second round D5) |
| The day-0 jump read from **(A_i − Ā)/s_i** around company means | A_i/s_i (the first build) | The gate simulates the null: the tested mean (H1's crush) must not enter its parameters; with s_i varying within a company it did | none: firm effects and the scale never read it (§9, second round D4) |
| Robustness rows that G1 finds **mis-sized keep their estimate and lose their p-value** (ADR 0005 §4) | Report the p-value beside a caveat (the first build) | ADR 0005 §4 drops rows "known to be mis-sized … so that no reader is misled" | `g1_size`, `g1_reps` and a `note` in `tests.json` say why (§9 F6) |
| A robustness rate **within one point of 6.30% is re-measured on 10,000** replications and decided against 5.57%, the bar for that count | Decide every row on its 2,000-replication rate | Near the bar a 2,000 block decides by luck (binomial sd ≈ 0.5 points): H4's sign test read 6.45% and BMP 6.00% there, 6.06% and 6.03% on 10,000 (delta review) | 10,000 more replications of the calibrated design, 27 s here (§9, second round D3) |
| Holm over **all seven** declared hypotheses, H5–H7 at p = 1 | Holm over H1–H4 (m = 4) | m = 4 would shrink the multiplier after seeing part of the family; p = 1 gives an upper bound that milestone 4 can only lower (`test_an_untested_hypothesis_at_one_is_an_upper_bound`) | H1–H4 face the m = 7 thresholds now |
| The `mixed` and `coarse` minimum counts **span changes of up to 2 sessions** across unobserved sessions | One-session changes everywhere | Mon/Wed/Fri baselines have almost no one-session changes, so the literal rule would empty both samples (ADR 0004 §4) | A default the owner can override (`params.yaml`), now recorded in ADR 0004's dated note. Even so, 718 of 845 coarse events and 13 of 48 mixed ones fail the minimum |
| s_i and SA built for **daily** only | The ADR's span-change scale for coarse | Coarse and mixed are exploratory; their scale correction is not built | No standardised robustness rows outside `daily` |
| Season clusters merged **within each test's event set** | One merge for all | ADR 0005 §2b says "in the test's event set" | RUNUP gets 8 seasons, PERSIST_10 gets 7; H2's Holm pass depends on that count (§6.2, §9 F1) |
| A computed caveat in `tests.json` naming every robustness row that G1 found oversized, and a note on each such row | Leave the G1 table to speak | A reader of a robustness row should not need to cross-read the gate | The caveat changes with the gate's numbers |

## 4. Data flow

```
 stage: events, eps, iv_daily, event_iv, market_daily (ln VIX, local), chain_expiry (local), session
        │ panel/run.py: build_panel -> measures (base_ok -> beta -> ALIV, e -> eligibility -> s, R-hat, SA) -> front_fixed_ivs
        ▼
 event_window_obs (89,389 rows)  event_measures (1,353 rows)   stage: every column; data/derived: no _cboe column
        │ stats/run.py --g1: designs from the real windows, calibrate() on cm30 (H1-H3) and on sigma_d (H4),
        │                    2,000 replications x 33 designs (calibrated, 18 stress, 14 power points);
        │                    robustness rates near the bar again on 10,000 (calibrated)
        ▼
 stage/g1_report.json  (verdicts: H1-H4 pass; the re-measured rates)
        │ stats/run.py result_rows: suite.one_session / suite.ramp per test -> withhold G1-oversized robustness
        │               rows -> Holm (H1-H7) -> H2's season cut -> BH -> paths -> G1 rows
        ▼
 results (786 rows; the invariant runs on the write)   stage + data/derived
        │ tools/export_app_data.py (committed tables only)
        ▼
 app/public/data: tests.json, event_paths.json, terrain.json, heatmap.json (+ meta, sample_funnel, iv_measures at 0.4.0)
```
