# Milestone 0 methodology: adversarial validation ledger

*Edited for publication: a reference to a local session scratch file was removed.*

- **Date:** 2026-10-28. **Scope:** ADRs 0002–0005, `docs/architecture/data-model.md`, `docs/concepts/00-background.md`,
  `research/prototypes/*`, `data/derived/earnings_calendar_30_large_caps.json`, `docs/prfaq.md` (Internal FAQ).
- **Method:** the `evidence-gated-validation` skill, Tier 2 (two channels) for every numeric, statistical and
  literature claim, Tier 1 for the rest. Default verdict on every claim: broken.
- **Mode:** hybrid.
  - Channel A for the literature and the NYSE calendar was done by an independent sub-agent. It worked from the frozen
    claims ledger, never saw a probe, and verified every claim against primary sources only.
  - Where the "documentation" is the ADR text itself, I read it myself (single-context fallback). Those cells are
    marked *spec*.
  - Agreement is therefore "dual-confirmed (hybrid)", not independent proof.
- **Environment:**
  - Python 3.12.13, numpy 2.5.4, scipy 1.18.1, pandas 3.1.0, statsmodels 0.15.0, uv 0.11.25.
  - `exchange_calendars` 4.13.2 is not a project dependency. It was overlaid ephemerally with
    `uv run --no-sync --frozen --with exchange_calendars`, using a scratch uv cache.
  - `uv.lock`, `pyproject.toml` and every `research/prototypes/*.py` had the same md5 before and after.
- **Probes:** `docs/validation/probes/m0-methodology/`. Every probe runs from the repo root with
  `uv run --no-sync --frozen python <probe>`. p01 and p05 also need `--with exchange_calendars`.
- **Not run:** no `dolt` command and no DoltHub query.
- **Network:** p10 makes one Crossref GET per DOI.
- **Files touched:** nothing outside this file and the probe folder. Nothing was committed.

## Single most important fix, and one deletion

- **Fix first:** ADR 0005's primary statistic for H2/H3 (claim 7d in practice, plus N7).
  1. Specify the R̂ estimator.
  2. Make the milestone-3 design 5 use the *estimated* R̂ at the real N, not the true R.
  3. Until it passes, make the date- or ISO-week-clustered CS-t primary for H2/H3.
  - The same work should restate H1–H4's nulls to match BMP's precision-weighted estimand (7b).
- **Delete:** `kp_t` as specified ("standard KP as published", r̄ over all pairs).
  - Under partial clustering it is not what the published literature prescribes: KPP (2018) is the published procedure for that case.
  - It rejects 0% in the ADR's own table, so it can only mislead a reader.
  - Replace it with KPP's average-overlap statistic as the citation-backed robustness row.
